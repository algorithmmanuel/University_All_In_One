# Architecture and audit context

Reviewed source: algorithmmanuel/University_All_In_One at c1e494e533965cf10e701bd4b851cb4f3fb3b7db, immutable GitHub-blob-verified snapshot. Scope: api/, web/, scripts/, compose.yaml and .github/workflows/. Historical Android app/, other products, live control planes and imported audit tooling are excluded. No compatible prior coverage ledger/findings was available; older hardening documents are context, not covered units. Profile standard; no strict agent budget.

EduCyber is a browser learning platform. Anonymous visitors read published catalogues, mission manifests and health, register/login and request account recovery. Adult students can enrol, read lessons, save completion, take practice assessments, run fictional investigations and submit feedback. Teachers register inactive; approved teachers/admins have a small protected workspace. Minors remain inactive pending guardian verification; age is self-declared. Operator CLI utilities manage beta invitation slots and database maintenance (api/auth_routes.py:40; api/age_policy.py:25; api/create_beta_invites.py:15; api/reassign_beta_invite.py:11).

FastAPI assembles routers, CORS and telemetry in api/main.py:42. PostgreSQL is accessed through SQLAlchemy/psycopg, with Alembic migrations and models for identity/session digests, invitation/reset digests, courses/lessons, enrolment/progress, quiz attempts, mission runs and feedback (api/database.py:5; api/models.py). Next.js/React/TypeScript renders the frontend; Three.js is a simulated mission UI, not a live command executor (web/package.json; web/app/missions/MissionWorkspace.tsx).

Identity enters through JSON credentials, date/role/invite fields and Authorization bearer values. Fixed scrypt policy and SHA256 session lookup protect passwords/tokens; current account activity and optional private-beta eligibility are rechecked per request (api/password_security.py:19; api/auth.py:23). Registration accepts student/teacher roles only. Private-beta redemption locks an unredeemed invite. Login and registration counters use PostgreSQL upserts keyed by normalized email/purpose (api/auth_routes.py:40; api/login_limiter.py:20). These are source controls, not proof of deployed edge enforcement.

Recovery accepts email and later a bearer reset capability. It validates operator mail/origin settings, stores random-token digests, sends a reset link to a fixed Brevo HTTPS endpoint, checks token expiry/use under row locks, changes the user's password and deletes existing sessions (api/password_recovery.py:44,81,130). External mail must be mocked for any future local check. No real provider calls or paid quota.

Learning helpers require student identity, published course and own enrolment before lesson/progress operations (api/learning_routes.py:12,21). Quiz routes reuse eligibility, recompute deterministic server selections and grade exact answer sets with strict indices, preserving a legacy full-bank path; history binds to user/course (api/quiz_routes.py:13,34,52; api/assessment_selection.py:21,37). Practice answer explanations are intentional, not a confidential exam key guarantee.

Mission creation derives owner/initial score from the server. Resume checks ownership; decisions use owner-scoped row locking, expected-step/completion checks and server-owned points; history filters current user (api/mission_routes.py:18,54,76,121). Feedback derives ownership from current_user and filters reads (api/beta_routes.py:23,38). Review alternate/legacy paths and derived copies rather than assuming helper presence proves isolation.

Browser forms and API responses feed React text/controls, URL-query state, scene state and sessionStorage bearer copies. Authenticated fetches attach Authorization; logout attempts server revocation and clears local storage. Next rewrites API/health requests to a validated operator API origin; server-rendered pathway lookup has a separate frontend-origin setting (web/app/account/page.tsx:44; web/components/home/account-navigation.tsx:17; web/next.config.mjs:15; web/config/api-origin.mjs:2; web/lib/api.ts:4). Explicit-origin CORS disallows credentialed cookies. Browser policy/header/deployed-origin effects remain unobserved.

Runtime source includes loopback PostgreSQL Compose services, production configuration assertions and separate development launch guards. Production edge/backups flags are attestations, not implementations (compose.yaml; api/production_config.py:6; scripts/development.py:45). Operational paths include seeding, invitation reassignment, migrations/backups, retention and Git synchronisation/scheduled tasks. Their source/CLI authority differs from web-user authority.

CI uses pull_request/push, declared contents:read, lockfiles, ephemeral PostgreSQL, mocked gameplay and real API/browser jobs.
