# Decision workshop authoring and security contract

The library contains 24 original conceptual cases in `api/content/journey_workshops_v1.json`, exactly three for each of the eight journey stages. Each has three decisions, two choices per decision and a pinned `workshops-v1` revision. The strict Pydantic loader rejects unknown fields, duplicate IDs, unsupported stages and malformed/bounded text or effort. Choices use `a`/`b` identifiers; display order varies deterministically. Supported findings and unresolved decisions are authored explanations, not empirical risk or mastery measurements.

Write distinct evidence, prompts, explanations and objectives for each case; include no real exploit instructions, credentials or personal data. Current supported choices have a finding and effort two; unsupported choices explain the unresolved issue and effort one. Costs are simplified teaching units. Review the entire eight-path decision space for coherent explanations. Do not imply that completing the case proves competence or that one finding establishes a secure real system.

`api/journey_workshops/engine.py` retains a validated original snapshot and copy-on-write decisions/receipts. A live projection shows only the current offered choices and prior selected explanations. Same-opening replay starts from the owned completed attempt's snapshot and copies only its summary. Change the content revision and retain the old resolver when changing mechanics; never reinterpret saved attempts under incompatible rules.

`/api/v1/workshops/catalog` is public summary metadata. Saved history/start/resume/decisions require the existing eligible student session and user ownership; teacher/admin roles do not gain private review access. Clients submit only case ID, optional owned replay ID, or a UUID/expected step/offered choice. Four-KiB body bounds, creation limits, private no-store responses and paged owner history apply. PostgreSQL row locks serialize commands; state and receipt commit together. A same-payload UUID retry returns current saved state; changed-payload reuse or stale commands return 409. Transient storage failure returns a sanitized 503 and rolls back. The browser preserves UUIDs for retry after a lost response.

Migration `0013_journey_workshops` adds an independent table/index only. Extend beta preservation capture whenever adding another learner-data table. Tests in `api/test_workshops.py` cover all 192 choice paths, strict projections, owned real-session APIs, PostgreSQL conflicting/duplicate races, rollback and additive preservation. Actual-API browser tests cover desktop/mobile persistence, replay and lost-response retry. These checks do not replace independent content/comprehension review.
